Sync attribution back to Pipedrive

Tracking and this dashboard work on their own, but writing the journey onto a Person, Lead, or Deal's custom fields in Pipedrive needs one more thing: a webhook, so Pipedrive tells us the moment one of those exists.

Important: this doesn't create Person, Lead, or Deal records in Pipedrive — it only enriches ones that already exist. Your website's own contact form (or however leads reach you) still needs to create the Pipedrive Person itself; this just fills in where they came from once it does.

  1. In Pipedrive: Settings > Tools and apps > Webhooks > Create new webhook.
  2. Event action: * (all). Event object: select Person and Deal at minimum. Add Lead too if you want a permanent record of where each enquiry came from before it's converted to a Deal — see it under a Lead's "Marketing Attribution" fields once set. One webhook covering all five event objects at once works fine — no need for separate webhooks per object.

Log website visits to Pipedrive

Separate from the fields above (which keep a handful of summary fields current): this adds a record of each individual page visit — which page, how long they spent — onto the Person as they happen, once someone's identified in Pipedrive. Off by default since some reps find a per-visit feed noisy; turn it on if you'd like to see it.

Only visits of 3 seconds or longer are logged, to keep this useful rather than noisy. Deals only get tagged when a contact has exactly one open deal, to avoid guessing which one a visit relates to.

Lead source fallback

For leads that never visit your website at all — e.g. someone who fills out a native Facebook Lead Form that a tool like WhatConverts or Zapier pushes straight into Pipedrive — there's no tracked journey to show. If your Pipedrive Leads already capture where those came from, add the field(s) below and they'll be used as that contact's first-touch source, but only when they have no other tracked activity at all. It never overrides real tracked data.

Add more than one if different intake channels use different fields (e.g. a web form vs. WhatsApp) — they're checked in order, top to bottom, and the first one with a value on a given lead wins.

Google Ads conversion feedback

Tell Google Ads which ad clicks actually became real leads and customers, so its bidding learns to find more like them (and fewer like the ones that didn't). This downloads a file of Deal-created and Deal-won events, matched to the original ad click — upload it in Google Ads under Tools and settings → Conversions → Uploads.

One-time setup needed first: create two import-type Conversion Actions in Google Ads named exactly CRM Deal Created and CRM Deal Won (the names must match character-for-character). Only prospects whose first touch was a Google ad click are included — there's nothing to match a conversion to otherwise.

Microsoft Ads conversion feedback

Same idea, for Microsoft Advertising (Bing) — closes the loop between what actually became a lead or customer and the ad click that brought them in. Upload it under Tools → Conversion Tracking → Conversion Goals, using the Upload a file option.

One-time setup needed first: create two Offline Conversion goals in Microsoft Advertising named exactly CRM Deal Created and CRM Deal Won. Microsoft requires waiting at least 2 hours after creating a new goal before its first upload. Only prospects whose first touch was a Microsoft/Bing ad click are included.

LinkedIn Ads conversion feedback

Worth checking before your first upload: LinkedIn matches primarily on hashed email, not a click ID directly — that's what this file uses. This one's less battle-tested than the Google/Microsoft exports above, since LinkedIn's exact template wasn't available to confirm against. Tracking social traffic

Paid social (Facebook/Instagram Ads, LinkedIn Ads, etc.) works the same way as Google/Bing Ads: add UTM parameters to the ad's destination URL in the ad platform itself (e.g. ?utm_source=facebook&utm_medium=cpc&utm_campaign=...). Facebook and Instagram click IDs (fbclid) are also captured automatically when the platform appends one, the same way gclid is for Google Ads.

Organic social (someone clicks a link in a LinkedIn/Facebook/Instagram/X/TikTok post, with no ad or UTM involved) is detected automatically from the referring site and shown as its own "Organic social" channel — no setup needed. The one thing worth knowing: several platforms' in-app browsers (particularly Facebook, Instagram, and TikTok on mobile) strip the referrer for privacy, so a real organic-social click can occasionally show up as generic website traffic instead. For guaranteed accuracy — especially for a bio link or a post you'll want reliable numbers on — add UTM parameters to that link too (e.g. ?utm_source=linkedin&utm_medium=social&utm_campaign=launch-post), the same as you would for an email link.

Assisted conversions

Unlike every other report here (all first-touch), this looks at a Won deal's ENTIRE journey — which channels showed up anywhere along the way, not just the first or last one. Surfaces assist channels like retargeting or email nurture that never get credit under first/last-touch attribution. Rows don't sum to 100%: a single Won deal's journey can touch several channels, each counted.

Deal stage by source
